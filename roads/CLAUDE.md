# roads — эволюция дорожной сети между городами (дерево Штейнера)

Учебный проект: генетический алгоритм строит сеть дорог между городами наименьшей длины (дерево Штейнера).
Три режима: компромисс стройки и поездок (по умолчанию, `TASK.mode = 'routes'`, ползунок w = `tripShare`), самая короткая сеть
с дорогами в геноме (`'roads'`) и «строит алгоритм» (`'tree'`: дороги — остов Прима, в геноме только развилки).
Тот же алгоритм, что в `../roof` и `../teo-leg`: турнир из трёх, худший умирает, потомок с одной мутацией. Видов нет.

**Главная цель — понятность для обучения.** Каждая часть системы — отдельный файл с комментариями.

## Архитектура

Обычные `<script>` в фиксированном порядке, глобальные функции. Без модулей и зависимостей (ради `file://`).

| Файл | Роль |
|---|---|
| `js/rng.js` | Генератор с seed (копия из `roof`) |
| `js/roads.js` | `MAP_W`/`MAP_H`, `TASK` (map, cities, mapSeed, mode), `CITIES`, `makeCities` (решётки, пресеты и случайные с минимальным зазором), `maxJunctions` (n − 2), `randomRoads`/`crossover`/`mutate` — диспетчеры на `*Tree` и `*Free` по режиму; `nextJunctionId` (номера развилок для дорог), `randomCut` |
| `js/fitness.js` | `mst` (Прим O(V²)), `fermatPoint` (Вейсфельд), `exactJunctions` (точные ответы пресетов), `setTask` + `REFS` (mst, bound, exact — всегда через остов), `classify`, `evaluateRoads` → `evaluateTree` / `evaluateFree` (union-find: связность, кольца), `junctionStats` (степени и углы) |
| `js/evolution.js` | Класс `Evolution`: турнир из трёх, история `{counts, best, length}`, `stopReason` (близость к точному ответу — только пресеты) |
| `js/draw.js` | Карта (сеть, развилки по цвету, пунктиром остов), график пула с длиной лучшей и эталонами |
| `js/app.js` | UI: кнопки, цикл `requestAnimationFrame` с ограничением скорости (поколений/с), панели |

## Логика модели

- Геном: `{ junctions: [{x, y}] }` (режим `tree`) или `{ junctions: [{id, x, y}], roads: [[a, b]] }` (режим `roads`).
  Ключ узла в дороге: город — индекс 0…n−1, развилка — её `id` (счётчик `nextJunctionId`, сбрасывается в `setTask` до n;
  счётчик глобальный, поэтому прогон воспроизводим только с начала).
- `tree`: дороги — остов Прима по городам и развилкам. `roads`/`routes`: дороги из генома как есть; `addCrossroads`
  режет пересекающиеся дороги (кроме общих концов) и добавляет узлы-перекрёстки после развилок (`firstCrossroads`,
  `junctionStats` → `crossroads: true`). Длина считается по исходным дорогам, связность и поездки — по разрезанным
  (`edges`), `roadCount` — число дорог генома. Union-find даёт связность, `linked`, `share` и `extra` (куски, замыкающие кольца;
  пересечение внутри связной сети тоже кольцо). Остов Прима никогда не пересекает себя, поэтому в `tree` перекрёстков нет.
- Стоимость `cost`: `routes` — (1 − w)·L / L_остова + w·T / T_прямо, T — средний кратчайший путь между парами городов
  (`tripStats`: Дейкстра O(V²) от каждого города), T_прямо = `REFS.straight` (`averageStraight`), ещё `detour` — средний крюк;
  остальные режимы — L. `setTripShare` + `Evolution.rescore()` — смена ползунка на ходу: пул переоценивается, геномы те же.
- `maxJunctions`: n − 2 (`tree`, `roads`), 2n (`routes`: в сети с кольцами перекрёстки становятся развилками).
- Оценка: не все города связаны → `share` (0..1); иначе 1 + C_остова / C. Порядок сетей в режиме `tree` от сдвига на 1
  не изменился, эталоны режима `tree` прежние.
- Классы `routes` (`ROUTE_CLASSES`): не все связаны / хуже остова / как остов / лучше: дерево / лучше: с кольцами (`extra` > 0).
  `CLASS_NAMES` выбирается в `setTask`, легенда графика перестраивается в `reset`. Точного ответа в `routes` нет.
- Классы остальных режимов: не все города связаны / длиннее остова / как остов (±0,01 %) / короче / короче и все развилки степени ≥ 3 —
  три дороги под 120° ± 5° / точный ответ (±0,01 %, только пресеты).
- Мутации `tree`: малый сдвиг σ = 1 км (40 %), большой σ = 10 км (15 %), новая рядом с узлом σ = 6 км (15 %) или в случайном
  месте (10 %), удаление (20 %). Мутации `roads`: дорога к одному из 4 ближайших (20 %) или случайная (5 %), удаление
  дороги (15 %), перенос конца (10 %), развилка на дороге (15 %), деление узла степени ≥ 2 (5 %), перекрёсток → развилка генома (5 %,
  `segmentCrossing`), сдвиг развилки малый (15 %) / большой (5 %), удаление развилки с цепочкой соседей (5 %). Невозможная операция заменяется возможной.
- Нижняя граница √3/2 · остов (отношение Штейнера) — только в таблице, на графике не видна: до неё 13 %.
- График: стоимость лучшей (`cost`) только у связных сетей (`null` иначе), шкала ограничена 1,3 × остов.

## Важные решения и грабли

- **Классы по форме, а не по процентам.** Сначала классы были «короче остова на <1 % / 1–3 % / >3 %», но выигрыш
  зависит от карты (20 городов seed 1 — максимум 1,9 %), и верхний класс был недостижим. Теперь классы — «короче»
  и «короче, все развилки под 120°»: это и есть урок проекта.
- **«Почти не улучшается» (замечание пользователя).** На случайных городах выигрыш у остова 2–5 % — свойство задачи
  (для случайных точек остов почти оптимален), а в стартовом пуле были сети без развилок, то есть готовый остов.
  Закрыто: в стартовом пуле у каждой сети хотя бы одна развилка, треугольная решётка (выигрыш 13 %,
  почти предел √3/2). Квадратная сетка — ~7,4 %.
- **«Откуда берётся хорошая стартовая сеть» (вопрос пользователя).** В режиме `tree` дороги прокладывает точный алгоритм,
  поэтому даже случайные развилки дают почти остов, и эволюции не видно. Добавлен режим `roads` (дороги в геноме) и сделан
  режимом по умолчанию: старт — паутина вдвое длиннее остова с несвязанными городами.
- **Ловушки режима `roads`.** (1) Изгиб a—b—c не превращается в Y, а крест из 4 дорог — в две развилки по 3: каждый промежуточный
  шаг удлиняет сеть. Квадрат застревал на остове или на кресте (+3,5 %). Закрыто мутацией «деление узла» (степень ≥ 2).
  (2) Все n − 2 места для развилок занимали развилки без дорог, и новые развилки не появлялись. Закрыто: при полном лимите
  «развилка на дороге» и «деление» удаляют случайную развилку.
- **Компромисс стройки и поездок (запрос пользователя).** Без стоимости стройки оптимум — прямая дорога между каждой парой,
  поэтому стоимость смешивает стройку и поездки, все пары городов равны (население не вводили). Сначала было L + k·T
  с k = 0…300 по логарифмической шкале; по просьбе пользователя — ползунок 0–100 % «короче дороги / быстрее добраться»
  и нормированная смесь (обе части = 1 у эталона). 75 % по умолчанию — несколько колец; 90 % — почти сетка.
- **Пересечения дорог (замечание пользователя на 40 городах).** Пересекающиеся дороги считались эстакадой: точка
  пересечения не связывала сеть и по ней нельзя было свернуть. Теперь это перекрёсток (`addCrossroads`). Это открыло
  ловушку «крест»: две диагонали квадрата с перекрёстком в центре (+3,5 % к ответу), решётка упала до 8–9 %, случайные
  20 городов seed 2 — длиннее остова. Перекрёстка нет в геноме, делить нечего. Закрыто мутацией «перекрёсток → развилка».
- **По умолчанию (выбор пользователя):** режим `routes`, ползунок 75 %, карта — 20 случайных городов; кружок города 18 px (`CITY_RADIUS`),
  города рисуются поверх дорог, развилки поверх городов. Стартовый пул в режимах с дорогами в геноме — пустая карта
  (ни дорог, ни развилок), пунктир остова по умолчанию выключен: «изначально карта без рёбер». Раньше старт был паутиной
  из n/2…2n случайных дорог — ответы те же.
- **Скорость.** На 3–20 городах эволюция сходится за секунды, поэтому есть ограничитель «поколений/с».
- Подсчёт углов (`junctionStats`) в каждой оценке нужен для классов и роняет скорость примерно вдвое — терпимо.
- Шестиугольник — нарочно: для правильного n-угольника при n ≥ 6 лучшая сеть = остов, развилки не помогают.

## Идеи на перспективу

- Перетаскивать города мышью и смотреть, как сеть перестраивается.
- Коммивояжёр вторым режимом (геном — перестановка, мутация — разворот отрезка).
- Надёжная сеть: связность после обрыва любой одной дороги (уже не дерево) — компромисс длины и надёжности.
- Стоимость местности (реки, горы) — дороги перестают быть прямыми.
- Толщина дороги по загрузке (сколько кратчайших путей через неё идёт) — видны магистрали.
- Население городов: поездок между городами пропорционально произведению населений (гравитационная модель).
