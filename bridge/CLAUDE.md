# bridge — эволюция фермы моста над случайной долиной

Учебный проект: генетический алгоритм собирает ферму (стержни + шарниры), которая держит дорогу через долину,
и минимизирует массу стали. Эталон — ферма Уоррена, подобранная под ту же долину.
Тот же алгоритм, что в `../roof` и `../roads`: турнир из трёх, худший умирает, потомок с одной мутацией. Видов нет.
Запрос пользователя: «фантастические, но рабочие фермы» — свобода топологии и опор, честная проверка прочности.

**Главная цель — понятность для обучения.** Каждая часть системы — отдельный файл с комментариями.

## Запуск и проверка

- Браузер: открыть `index.html` (работает с `file://`, без сервера и интернета).
- Без браузера: `node tools/headless.js [поколений] [пул] [seed] [seed долины]` — те же `js/*.js` через `vm`;
  6-й аргумент — цель `light` (по умолчанию; на странице по умолчанию `budget`, выбор в `cfg-mode`), `strength` или `budget`, 7-й — множитель бюджета (1); `EVERY=n` — отчёт каждые n поколений, `DUMP=файл.json` — сохранить долину и лучший геном.
  Скорость ~4–7 тыс. спариваний/с (500 поколений × пул 300 — 25–40 с); шарниры на пересечениях замедлили на ~35 %
  (в пуле больше узлов: 32 вместо 24 в среднем; сам поиск пересечений — ~9 % времени).
- Эталоны (пул 300, 500 поколений, seed 1; ферма Уоррена → лучший мост):
  - долина 1 (44 м): 6,21 → 4,81 т; долина 2 (40 м, скала): 5,11 → 3,30 т; долина 3 (52 м): 8,95 → 4,22 т;
  - долина 4 (32 м, глубокая): 3,29 → 2,67 т; долина 5 (40 м): 5,11 → 4,18 т.
  - цель `strength` (u·M Уоррена → u·M лучшего, масса, загрузка): долина 1: 5,90 → 2,58 т (6,54 т, 39%);
    долина 2: 4,87 → 2,60 т (6,26 т, 42%); долина 3: 8,45 → 2,96; долина 4: 3,10 → 2,88; долина 5: 4,87 → 3,23 т.
  - цель `budget`, 1000 поколений (запас прочности: Уоррен из той же стали → лучший мост): бюджет ×1 — долина 1: ×0,99 → ×1,56;
    долина 2: ×1,05 → ×1,68; долина 3: ×1,03 → ×2,96; долина 4: ×1,06 → ×1,44; долина 5: ×1,05 → ×2,17.
    Прогиб лучшего моста `budget` в 2–11 раз меньше, чем у Уоррена (долина 1: 32 мм против 91).
    Разброс между seed заметный (долина 1, light: 3,06…3,97 т на seed 1–3) — сравнивать на нескольких.
  Если цифры изменились, значит, поменялась модель, оценка или последовательность вызовов rng.
- Проверка решателя: треугольник 4 × 2 м под 100 кН — оба стержня −70,71 кН; стержень — удлинение FL/EA;
  квадрат без диагонали — механизм 1, с диагональю — 0.
- Скриншот без браузера: headless Chrome `--screenshot --allow-file-access-from-files` по `file://` на временную копию
  `index.html` в scratchpad с абсолютными путями к `js/` и скриптом, который жмёт `btn-gen`.
- **Грабли окружения:** ночью машина бывает загружена (mediaanalysisd, mds), и долгие прогоны идут в 20–40 раз медленнее.
  Сначала замерить короткий прогон, а не искать зацикливание в коде.

## Архитектура

Обычные `<script>` в фиксированном порядке, глобальные функции. Без модулей и зависимостей (ради `file://`).

| Файл | Роль |
|---|---|
| `js/rng.js` | Генератор с seed (копия из `roof`) |
| `js/terrain.js` | `DECK_STEP` = 4 м, `TASK` (terrainSeed, mode), `TERRAIN`, `makeTerrain` (свой rng от seed долины), `groundY`, `inRiver`, `placeNode`, `isSupport`, `barInGround` |
| `js/truss.js` | `makeTruss(nodes, bars)`: плотная матрица 2N × 2N, Холецкий с подсчётом нулевых опорных элементов (`mechanism`), `solve(loads)` → усилия и сдвиги; одна факторизация на все нагрузки |
| `js/bridge.js` | `SECTIONS` (8 труб, ×1,5), геном, `nextNodeId`, `randomBridge`, `crossover` (разрез прямой), `mutate` |
| `js/fitness.js` | Нагрузки и проверки, `evaluateBridge(genome, detail)`, `classify`, `REFS.warren` (`warrenGenome` + `sizeUp`), `setTask` |
| `js/evolution.js` | Класс `Evolution`: турнир, история `{counts, best, mass}`, `stopReason` (застой, предел) |
| `js/draw.js` | Долина, мост (цвет — усилие, толщина — сечение, прогиб ×N), грузовик, график пула |
| `js/app.js` | UI, цикл `requestAnimationFrame` с ограничением скорости, панели; показанный мост переоценивается с `detail` |

## Логика модели

- Координаты в метрах, дорога на y = 0 от x = 0 до span, узлы дороги — ключи 0…D−1, свободные узлы — `id` ≥ D.
  Концы дороги — опоры. Звенья дороги `[i, i+1]` в геноме, мутации их не удаляют.
- Узел в грунте поднимается на поверхность и становится опорой (`isSupport`), в воде — на уровень воды, не опора.
  Узлы ограничены: x ∈ [−0,2; 1,2] × span, y ≤ 0,35 × span.
- В расчёт идёт только часть, связанная с дорогой (обход от узлов дороги, через опоры не проходит).
  Стержни сквозь грунт и несвязанные куски не работают, но их масса считается.
- Пересечения стержней — шарниры (`joinCrossings`): стержень режется на куски, геном не меняется. `result.bars` — куски
  (`bar.e` — номер стержня в геноме), узлы пересечений — в `result.pts` с `cross: true`. Ближе 5 см к концу — не режем.
- Нагрузки: дорога 20 кН/м, вес стали (78,5 кН/м³), грузовик 300 кН в каждом внутреннем узле дороги по очереди;
  огибающая по положениям. Проверки: растяжение ≤ 200 МПа, сжатие ≤ min(200 МПа · A, π²EI/L²), сдвиг любого узла (не только прогиб дороги) ≤ span / 250.
- Оценка: механизм → 0,5 / (1 + m); ломается → 0,5 + 0,5 / u; держит → 1 + C_Уоррена / C, стоимость C = `bridgeCost`:
  цель `light` — M, цель `strength` — u·M (сталь на единицу прочности). Цель `budget` — своя ветка `classify`:
  в бюджете 1 + S / S_Уоррена (S = 1 / u, u ≤ 1 не требуется), дороже — 0,5 + 0,5·x/(1+x), x = S/S_W·(B/M)^4.
  Бюджет `TASK.budget` = `budgetFactor` × масса самой лёгкой фермы Уоррена; эталон — `fillBudget` (утолщать самый
  загруженный стержень, пока хватает стали), лучшая высота по S. Названия классов 2–4 зависят от цели:
  `setTask` вставляет `MODE_CLASS_NAMES[mode]` в `CLASS_NAMES`. Уоррен выбирается по той же стоимости.
- Классы: складывается / стоит, но ломается / держит, не легче эталона / легче эталона / легче в 1,5 раза.
- Эталон Уоррена: высоты span/4…span/12, сечения подбираются циклом «перегруженные на ступень толще»
  (если не проходит только прогиб — толще все). Берётся самый лёгкий.
- Мутации: стержень к одному из 4 ближайших (22 %), треугольник на стержне (15 %), узел на стержне (8 %),
  удаление стержня (13 %), сечение ±1 (17 %), сдвиг узла малый σ = 0,5 м (12 %) / большой σ = 3 м (6 %),
  удаление узла со стержнями (7 %). Лимиты: 40 свободных узлов, 160 стержней.

## Важные решения и грабли

- **Оценка механизма по числу свободных движений.** Старт — голая дорога (цепочка шарниров, D − 2 свободных движения).
  Если считать любой механизм нулём, у эволюции нет подсказки; со счётчиком первые стоящие мосты появляются за ~10 поколений.
- **8 сечений вместо 4.** С шагом ×2,5 пул застревал: у хорошего моста загрузка ~100 %, и утоньшение любой трубы его ломает.
  На долине 4 эволюция не могла обогнать Уоррена (4,43 т против 4,37). С шагом ×1,5 — 2,76 т против 3,29.
- **Цель «прочность на тонну стали» (u·M).** Пользователь видел мосты, которым «не хватает палочки»: в режиме `light`
  стержень, разгружающий слабое место, окупается только после нескольких утоньшений (две мутации подряд).
  С u·M он окупается сразу. «Сколько грузовиков выдержит на тонну стали» не годится: вес дороги постоянен и огромен
  (88 т на 44 м против 3–6 т стали), и толстые сечения выигрывали бы всегда. Поэтому увеличиваются все нагрузки
  разом (1/u), а u·M почти не зависит от масштаба сечений (самовес штрафует толстые, Эйлер поощряет).
  Держать грузовик (u ≤ 1) по-прежнему обязательно.
- **Сдвиг любого узла ≤ span/250, а не только прогиб дороги.** Узел на двух длинных стержнях под острым углом
  по линейному расчёту «держит», но сдвигается в 50–190 раз больше дороги (метры) — почти механизм; на рисунке
  с увеличением прогиба он улетал за край.
- **Масштаб прогиба на рисунке — один для всех (`SAG_DRAW` = 20).** Раньше он подгонялся под каждый мост
  (самый подвижный узел → span/25), и мост в 2,5 раза жёстче Уоррена выглядел так же прогнутым («эталон лучше?»).
  Меньше только у сломанных, если узел уходит дальше span/8.
- **Бюджет: не стена, а штраф (B/M)^4.** Со стеной (дороже бюджета → 0,5 + 0,5·B/M, без учёта прочности)
  долина 4 застревала на ×0,48 при эталоне ×1,06 (3 seed из 4): путь к хорошему мосту идёт через «чуть дороже».
  Степень 2 сильнее на бюджете ×1 (долина 1: ×2,56), но при ×0,5 весь пул так и остаётся дороже бюджета
  (Эйлер: утоньшение в k раз роняет S до k² раз). Потолок min(1, …) вместо x/(1+x) тоже ломал ×0,5 (все оценки = 1).
- Эталонные мосты зависят от `maxY` и всего, что трогает rng: при смене ограничений цифры в списке выше надо переснять.

## Идеи на перспективу

- Тросы (работают только на растяжение) — висячие и вантовые мосты; нужен итерационный расчёт (выключать провисшие).
- Несколько грузовиков сразу / поезд; ветер сбоку.
- Стоимость опоры (фундамент дороже стали) — меньше опор, больше пролёты.
- Анимация обрушения сломанного моста (нелинейная динамика).
